## **Introduction: The Need for Data Center Interconnection**

Many organizations distribute their applications and servers across multiple data centers located around the world. To manage these resources efficiently, **Data Center Interconnection (DCI)** is required—a system that enables these different sites to be connected seamlessly.

Without appropriate technology, several challenges arise:

- **Different IP addressing schemes:** Each data center may have its own IP configuration that is not compatible with the others.
- **Heterogeneous connectivity:** Some sites may be connected via high-speed fiber optics, others via Ethernet or copper‑based connections.
- **Application independence:** Applications should be able to run in any location without having to worry about the underlying network infrastructure or the local IP scheme.

## **The Limitations of Traditional VLANs**

Although VLANs (Virtual Local Area Networks) are commonly used to extend Layer 2 network segments, they have two main limitations that VXLAN aims to overcome:

1. **Limited scalability:** VLANs support only about **4,000** virtual networks.
2. **Layer 2 constraint:** VLANs are not natively routable, which limits their use in complex infrastructures that require traversal across Layer 3 networks.

## **What is VXLAN (Virtual Extensible LAN)?**

VXLAN is a technology designed to support modern, large-scale virtualized environments and the cloud. Compared to traditional VLANs, it offers significant advantages:

- **Massive capacity:** It can support up to **16 million** virtual networks.
- **Layer 3 routing:** VXLAN virtual networks can be interconnected via a Layer 3 network, making it very straightforward to route traffic across the public internet.

## **VXLAN Components and Operation**

To allow virtual machines (VMs) located in different data centers to communicate as if they were on the same local network, VXLAN uses several key components:

- **VXLAN Tunnel Endpoint (VTEP):** This is the endpoint of the VXLAN tunnel, often located on the top‑of‑rack switch or on the virtualization server. Each VTEP has its own specific IP address.
- **VXLAN Network Identifier (VNI):** This is an identifier that allows virtual networks to be properly associated across different sites. For example, VNI 2000 in one data center will communicate directly with VNI 2000 in another data center through the tunnel.

## **The Encapsulation Process and Tunneling**

The core of VXLAN is its ability to transport Ethernet frames over an existing IP network via a **tunnel**. The process works as follows:

1. **Original Frame:** Start with the standard Ethernet frame (composed of an Ethernet header, IP header, and payload) generated by the virtual machine.
2. **Encapsulation:** This original frame is inserted inside a **VXLAN header**. In turn, everything is packaged inside a **UDP** packet, then into an **IP** packet, and finally into a new **Ethernet frame** for transport.
3. **Transport and Decapsulation:** The packet travels through the VXLAN tunnel. Once it reaches its destination, the receiving VTEP removes the tunnel headers (decapsulation) and delivers the original Ethernet frame to the destination virtual machine.

Thanks to this mechanism, virtual machines located in physically distant data centers can communicate as if they were **directly connected** to each other.
