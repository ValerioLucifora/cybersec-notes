## **Cloud Computing Models**

### **Introduction to deployment models**

When deploying a cloud‑based application, it is essential to consider who needs to access it and from where.

- **Public Cloud:** Ideal if the application must be accessible to anyone on the Internet.
- **Private Cloud:** Used for applications intended strictly for internal use, often hosted in a virtualized on‑premises data center owned by the organization.
- **Hybrid Cloud:** A configuration that combines the use of public and private clouds to address different application requirements.

---

## **Software as a Service (SaaS)**

The **Software as a Service** model is commonly associated with "on‑demand" software.

- **Management:** The application is written and managed entirely by third parties. The user does not need to install software locally, nor handle updates or maintenance.
- **Access:** The user simply accesses the service via a browser, entering their credentials.
- **Data:** Data is stored on a third‑party cloud platform, enabling centralized management.
- **Examples:** Services such as Google Mail or Office 365 are typical examples of SaaS, where the user simply uses the ready‑to‑run application.

---

## **Infrastructure as a Service (IaaS)**

Also known as **Hardware as a Service (HaaS)** , this model provides the computing resources needed to run your own applications.

- **User responsibility:** In this model, the user is responsible for software installation, data management, and all necessary updates.
- **Control:** Although the application and data reside in the cloud, the user has much greater control over access and security compared to other models.
- **Example:** A common example is web service providers, where you can purchase usage time on a specific server that is made available on the Internet.

---

## **Platform as a Service (PaaS)**

The **Platform as a Service** model represents a middle ground between SaaS and IaaS.

- **Development:** The provider supplies all the tools and "building blocks" needed to build a custom application.
- **Division of responsibilities:** The PaaS provider is responsible for the underlying engine that runs the application, while the user is responsible for developing, customizing, and maintaining the applications they create.
- **Example:** Salesforce.com is an example of PaaS, as it offers the tools to create custom applications that run on their platform.

---

## **The Cloud Responsibility Matrix**

The choice of model depends on the level of responsibility an organization is willing to assume.

- **On‑Premises Solution:** The customer is responsible for everything, from data and applications down to the physical data center.
- **IaaS:** The provider manages the physical data center, networking, and the physical host; the customer manages everything else.
- **PaaS:** Some elements, such as network controls and applications, may be shared between customer and provider, but the customer remains responsible for accounts, devices, and data.
- **SaaS:** The provider assumes most of the responsibilities, including the entire application management. The customer remains responsible only for the upper layers, such as data and accounts.
